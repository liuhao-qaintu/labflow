# 测试与验收

验证关注权限、事务和执行行为；测试模型、内存数据库与真实服务检查分别记录，不能将功能通过数量当作问答准确率。

## 检查范围

| 范围 | 主要检查 |
| --- | --- |
| 账号与访问 | 普通用户、管理员与维护白名单，用户归属与公开响应 |
| 账号恢复 | 凭据查询、补充、过期、处理事务与密码版本 |
| 预约执行 | 用户确认、拒绝、中断保存和恢复 |
| MCP 协议 | stdio 工具发现、调用与 Agent 接入 |
| 前端 | 路由、凭据输入边界和生产构建 |

## 后端回归

完成环境与配置后，从项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -p 'test_*.py' -v
```

单元测试使用内存数据库，覆盖角色权限、用户归属、公开响应、申请凭据、密码版本、处理事务和初始化保护。

### 预约确认与checkpoint

```powershell
.\.venv\Scripts\python.exe backend/tests/check_hitl_checkpoint.py
.\.venv\Scripts\python.exe backend/tests/check_stream_hitl.py
```

确认流程检查使用测试模型与工具：准备写入时暂停；用户确认后执行；拒绝时不执行；保存状态后能够恢复。具体隔离配置与检查入口见对应脚本，不要将业务库配置当作可丢弃的测试数据。

## MCP协议检查

```powershell
.\.venv\Scripts\python.exe backend/tests/check_mcp.py
```

该检查启动真实 stdio 子进程，读取配置的数据库以验证工具发现、调用与 Agent 接入；Agent 部分使用测试模型。应在隔离配置和测试数据上运行。

## 前端检查

在 `frontend` 目录执行：

```powershell
node --test tests/*.test.js
npm.cmd run build
```

测试覆盖路由与凭据输入边界，构建用于检查前端产物能否生成。页面外观和完整业务过程需在实际浏览器中另外验收。

## 人工验收过程

### 查询、预约与审核

1. 使用普通用户查询一条真实存在的测试资源，核对位置和开放时段。
2. 向助手说明预约需求，检查查询结果与确认卡。
3. 先拒绝一次，确认没有新增预约；再发起一次并确认，核对待审核记录。
4. 由管理员审核，申请人重新查询结果。
5. 尝试错误日期或冲突时段，核对返回信息和业务记录。

### 账号恢复

1. 提交虚构测试账号的核验申请，保存凭据并查询进度。
2. 管理员要求补充材料，申请人补充后再次查看状态。
3. 核验并重置后，用凭据查看本次有效的初始密码。
4. 首次登录修改密码，核对旧登录凭据失效及旧申请停止交付密码。

### 隔离与初始化

- 不同用户不能读取或恢复彼此的 checkpoint；普通用户不能调用管理员或维护接口。
- 找回申请仅由指定管理员读取与处理，错误凭据、过期和重复处理被拒绝。
- 初始化遇到已有数据时拒绝执行，不能覆盖账号或预约。

MySQL 并发、跨资源预约约束及真实模型质量需在相应环境分别验证。发布说明中的指标应来自对应实际运行与复核，本项目介绍不填入未经验证的准确率或成功率。
